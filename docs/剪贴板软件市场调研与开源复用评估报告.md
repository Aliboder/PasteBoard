## 一、调研说明

### 1.1 调研范围

- **平台侧重**：Windows（本项目目标平台）；macOS / Linux 仅作简要对照。
- **软件类型**：剪贴板历史管理器、系统自带功能、附带剪贴板能力的工具（启动器、生产力套件）。
- **数据来源**：GitHub 仓库页面与 API、官方文档、官方 README。所有外部链接见[第八章](#八参考链接)。

### 1.2 什么是"剪贴板管理器"

操作系统自带的剪贴板只能保留**最近一次**复制的内容。剪贴板管理器常驻后台，**监听**系统剪贴板的每一次变化，把历史内容**持久化**存储，并在需要时允许用户**搜索、选择、重新粘贴**任意历史条目。成熟产品通常还提供：固定/收藏、分组、图片/文件支持、快捷键粘贴、忽略规则、云同步、加密等功能。

### 1.3 评估基准（针对我们的项目）

| 维度 | 说明 |
|---|---|
| 技术栈匹配度 | 是否 Python / PySide6 / 面向 Windows |
| 许可证 | 决定能否直接复制代码（见第五章各表） |
| 活跃度 | 最后更新时间、star 数、issue 响应 |
| 架构参考价值 | 模块划分、监听/存储/粘贴等核心逻辑是否值得学习 |
| 直接可复用性 | 代码能否"拿来就用"或稍作修改融入我们项目 |

## 二、市场主流剪贴板软件调研

### 2.1 Windows 平台

#### ① Windows 11 自带剪贴板历史（Win+V）

微软从 Windows 10（1809）起内置的剪贴板历史功能，是很多用户最先接触到的"剪贴板管理器"。

**功能特点**
- 按 `Win + V` 唤出历史面板，支持文本和图片。
- 支持**固定**（Pin）常用条目，可逐条删除。
- 登录 Microsoft 账户后支持**云同步**，可在多台设备间共享（含 SwiftKey 手机端）。
- 与系统安全设置联动：敏感内容（如密码）默认不进入历史。

**优点**
- 零安装、零成本，系统自带，最稳定。
- 无需任何第三方进程，安全可信。

**缺点**
- 功能极简：**没有分组、标签、无限历史、富格式处理**。
- 历史容量有限、无导入导出、无自定义快捷键（面板是系统级的）。
- 云同步依赖 Microsoft 账户与隐私设置，部分用户会主动关闭。
- 不支持对历史条目的脚本化/自动化处理。

> 结论：作为"默认兜底"，但无法满足进阶需求——这正是第三方剪贴板管理器的存在空间。

#### ② Microsoft PowerToys Advanced Paste（高级粘贴）

PowerToys 是微软官方开源（MIT）的效率工具集，其中的 **Advanced Paste** 模块定位是"粘贴增强"而非历史管理。

**功能特点**
- 默认快捷键 `Win + Shift + V` 打开高级粘贴窗口。
- 可把剪贴板内容即时转换：纯文本、Markdown、JSON 转表格、URL 提取等。
- 支持调用 AI 模型对粘贴内容做二次加工（需 OpenAI/Azure 密钥）。

**优点**
- 官方出品、持续维护、免费、开源。
- 对"粘贴后处理"场景很实用（如把网页复制的富文本变成纯文本）。

**缺点**
- **不提供剪贴板历史管理**（PowerToys 本身没有历史功能）。
- AI 能力需要额外配置密钥，且内容会发送到云端（隐私顾虑）。
- 定位是工具而非"管理器"，与本项目目标不同，但**格式转换思路值得借鉴**。

#### ③ CopyQ — 功能最全面的开源剪贴板管理器

- **语言/框架**：C++ / Qt
- **许可**：GPL-3.0
- **GitHub**：约 12.1k star，6886 commits，持续维护，支持 Windows / macOS / Linux

**功能特点**
- 历史条目存入**标签页（Tabs）**，可拖拽排序、分组。
- 支持文本、HTML、图片、以及任意自定义格式。
- 内置**命令/脚本系统**：可为剪贴板变化挂载自动化动作（类似插件）。
- 条目可添加**备注与标签**；内置类 Vim 编辑器；系统级快捷键；托盘图标。
- 强大的命令行与脚本接口（`copyq copy/add/read ...`）。

**优点**
- 功能最全，几乎涵盖市面上所有剪贴板管理器能力。
- 跨平台，代码质量高、测试覆盖好（codecov 集成）。
- 脚本系统是它区别于竞品的最大亮点。

**缺点**
- **界面偏传统/老式**，大量功能堆叠导致设置复杂，学习成本高。
- 对普通用户而言"重"（功能过剩）。
- GPL-3.0 传染性较强，若想在其代码基础上做闭源/商业软件受限。

> 对我们的价值：功能清单与脚本系统可作**需求蓝本**；代码为 C++，**不能直接复用**，但架构思想（监听/存储/命令系统分层）很值得读源码借鉴。

#### ④ Ditto — Windows 老牌经典

- **语言/框架**：C++ / Win32
- **许可**：GPL-3.0
- **GitHub**：约 7k star，Windows 专属（也有 Windows Store 版）

**功能特点**
- 监听剪贴板并存入 **SQLite 数据库**，支持文本/图片/HTML/自定义格式。
- 默认热键 `Ctrl + ~` 唤出主窗口，双击或回车即粘贴回**上一个活动窗口**。
- 支持**分组**、**网络/局域网共享**（多机同步）、复制时**加密**、表达式替换。
- 便携版、无登录、无云、无遥测（"Local First"）。
- 支持忽略特定程序复制的内容。

**优点**
- Windows 平台最成熟稳定的方案之一，社区口碑好。
- SQLite 存储设计简洁可靠，历史容量大。
- "粘贴回上一窗口"这一交互是所有产品的标准范式，实现思路值得学习。

**缺点**
- **界面老旧**（视觉上仍是传统 Win32 风格）。
- 开发节奏偏慢，新功能少，主要由社区维护。
- 高级功能（网络共享、加密）配置较复杂。

> 对我们的价值：SQLite 存储、忽略规则、粘贴回上一窗口的实现是**Windows 上最好的参考**之一；代码 C++ 不可直接复用。

#### ⑤ ClipboardFusion — 商业软件代表

- **厂商**：Binary Fortress Software（免费版 + 付费专业版）
- 闭源商业软件，Windows / macOS。

**功能特点**
- 剪贴板历史（文本/HTML/图片）、搜索、固定。
- **云同步**（需账户）、**剪贴板加密**、**文本替换（text scrubber）**。
- **触发器/脚本动作**：复制内容后可自动执行处理（类似 CopyQ 命令系统）。
- 快捷键快捷粘贴。

**优点**
- 商业化打磨，界面现代、稳定性好、同步与加密开箱即用。
- 文本替换/动作触发器对提升效率非常实用。

**缺点**
- 云同步与高级功能需要**付费**/账号。
- 闭源，无法学习其实现。
- 免费版功能有明显裁剪。

> 对我们的价值：作为**功能参照**（云同步、加密、文本替换），不作为代码来源。

#### ⑥ 1Clipboard — 曾经的跨平台新秀（现已停更）

- **语言/框架**：Electron + Angular + TypeScript
- **许可**：仓库未声明开源许可证（license: null）
- **GitHub**：约 311 star，最后活跃提交约 2024 年，官网 1clipboard.io

**功能特点**
- 跨平台（Windows/macOS/Linux），支持**文件夹分类**、搜索、固定、多格式。
- 早期主打"所有设备共享一个剪贴板"。

**优点**
- 曾经 UI 现代、理念新颖（跨设备同步）。

**缺点**
- **基本停更**，多年无功能更新。
- 依赖 Electron 打包大、内存占用高。
- **无明确许可证** → 法律上**不可直接复用**其代码。
- 同步依赖其自有服务，目前已基本不可用。

> 对我们的价值：仅作历史参考（一个"Electron 方案最终停更"的案例）。Electron 路线与本项目技术栈不符。

#### ⑦ ClipX — 轻量级老古董

- 开源（Microsoft Public License 类似宽松许可），Windows。
- 约 2009 年起基本停更。

**功能特点**：极轻量、托盘图标、支持插件（缩略图、十六进制查看等）。

**优点**：极小、无依赖、启动即用。

**缺点**：年久失修、无现代特性（无搜索/无云/无分组）、与新系统兼容性存疑。

> 对我们的价值：几乎无。仅说明"轻量"也有市场，但功能过于简陋。

### 3.2 成熟产品的共同特性（= 我们的功能基准）

1. **后台常驻 + 系统托盘**，开机自启。
2. **事件驱动监听**剪贴板变化（而非轮询）。
3. **历史持久化**（SQLite / JSON / 文件），支持文本、HTML、图片、文件。
4. **搜索 + 固定/收藏 + 分组**。
5. **一键粘贴回上一个活动窗口**（全局热键唤醒，回车即粘贴）。
6. **忽略规则**（不记录密码框、指定程序）。
7. 高级产品再加：脚本/命令、加密、云/局域网同步、格式转换。

## 四、市场趋势小结

1. **"Local First" 回归**：Ditto 明确打出"无登录、无云、无遥测"；隐私敏感用户开始回避云同步。→ 本项目定位"本地"是有市场契合点的。
2. **历史 + 智能处理是分水岭**：免费/开源产品（CopyQ、Ditto）拼功能深度；商业产品（ClipboardFusion、Paste）拼 UI 与云；微软则用"系统内置 + PowerToys 智能粘贴"两条线覆盖基础需求。
3. **技术栈分化明显**：老牌 C++（CopyQ/Ditto）功能强但界面老；Electron 方案（1Clipboard）已证明会因性能/维护问题停更；Python/Qt 方案（jietuba）开始出现且表现不错。
4. **对我们的启示**：做"小而精"的本地剪贴板管理器，重点是**监听可靠、粘贴顺手、搜索快、界面现代**，而不是堆功能。

## 五、开源项目调研与可复用性评估

以下针对 **Python + PySide6 + Windows** 技术栈，逐个评估开源项目。星级说明：
- 🟢 **可直接复用**：许可证允许 + 语言/平台匹配。
- 🟡 **可参考**：可作为架构/思路蓝本，但代码不可（或不宜）直接搬。
- 🔴 **不可复用**：许可证禁止 / 平台不匹配 / 已废弃。

### 5.1 重点项目分析

#### ① jietuba（截图吧）— 最值得研究的同栈项目

- **仓库**：https://github.com/1003129155/jietuba
- **语言/框架**：Python + **PySide6**（核心）+ Rust（截图/OCR 加速）
- **许可**：MIT 🟢（宽松，可商用，注明出处即可）
- **活跃度**：126 star，最后推送 2026-08，**活跃维护**，仅支持 Windows 10+。

**项目结构（与我们最相关的剪贴板部分）**：
```
main/clipboard/
├── controllers/            # 历史加载、粘贴流程、右键菜单
│   ├── clipboard_controller.py
│   └── selection_manager.py
├── core/                   # 数据层
│   ├── manager.py          # ClipboardManager：数据存储、监听、粘贴 API
│   ├── models.py           # ClipboardItem / Group 数据模型
│   └── enums.py            # GroupType 分组类型
├── services/               # 服务层：文件 payload、分组规则、导入导出
│   ├── file_payload_service.py
│   ├── group_service.py
│   └── import_export_service.py
└── ui/                     # 界面层
    ├── windows/clipboard_window.py   # 历史窗口、搜索、预览、快捷粘贴
    ├── panels/group_bar.py
    └── widgets/...
```
其 `ClipboardManager` 核心职责包括：监听系统剪贴板变化、自动保存历史、支持文本/图片/HTML/文件、分组与收藏、搜索、快捷键粘贴、预览弹窗。配套还有核心模块 `core/shortcut_manager.py`（全局热键，基于 Windows API）、`core/platform_utils.py`（DPI 感知、AppUserModelID、进程管理等 Windows API 封装）。

**可复用性评估**：
- **架构上几乎完全对口**：监听 → 存储 → 模型 → 服务 → UI 的分层，正是我们想要的。
- **代码层面**：MIT 许可允许直接借鉴/复制并注明出处。剪贴板模块与 Qt 部分可借鉴；但其监听底层依赖自制 Rust 库 `pyclipboard`（仅 cp311-win_x64 的预编译 wheel），若我们不需要 Rust 加速，直接用 `QApplication.clipboard()` 的 `dataChanged` 信号即可，**不必引入其 Rust 依赖**。
- **注意**：仓库规模大（截图/OCR/GIF 等），只需抽取"剪贴板管理"相关部分即可，避免整体引入。

> **结论**：🟢 **本项目最重要的开源参考，架构与技术栈完全匹配，MIT 许可友好。**

#### ② InfiniteCopy — CopyQ 作者的 Python 版

- **仓库**：https://github.com/hluk/infinitecopy
- **语言/框架**：Python + Qt（QML 界面）
- **许可**：GPL-2.0 🔴
- **活跃度**：23 star，2026-08 仍在推送，跨平台。

**特点**：极简跨平台剪贴板管理器；最有价值的是**插件机制**——用户在配置目录放 Python 模块即可在剪贴板变化时执行自定义动作（`pre.py` / `post.py` 钩子）；用 `uv` 管理依赖；有 pytest 测试。

**可复用性评估**：
- **代码不可直接搬**（GPL-2.0 传染，会让本项目变 GPL）。
- **架构思想可参考**：①"pre/post 钩子"设计 → 可演化为我们的"剪贴板动作"扩展点；② 跨平台剪贴板监听（Qt 信号）写法；③ 项目很小，源码适合通读学习。

> **结论**：🟡 参考其**插件机制与监听写法**，代码不搬。

#### ③ clipster — Python 老牌 CLI 剪贴板管理器

- **仓库**：https://github.com/mrichar1/clipster
- **语言**：Python，CLI，面向 *nix（X11/Wayland）
- **许可**：AGPL-3.0 🔴（传染性强）
- **活跃度**：249 star，但 2022 年后基本停更。

**可复用性评估**：无 GUI、不面向 Windows、AGPL 传染性强。**三项全不满足**。

> **结论**：🔴 不可复用，仅作历史了解。

#### ④ Smart-Clipboard — Windows + Python 小项目

- **仓库**：https://github.com/ezeiq7/Smart-Clipboard
- **语言**：Python + tkinter，Windows
- **许可**：自定义（NOASSERTION）🔴（无标准开源许可，法律上谨慎）
- **活跃度**：16 star，2026-06 有推送。

**特点**：宣称支持即时搜索、模板、隐私模式、快捷粘贴启动器——与我们想法相近，但用 tkinter 而非 Qt。

**可复用性评估**：许可证不明（**不可直接复用**）；技术栈是 tkinter（与我们的 PySide6 不同）；规模小、文档少。可作为"Windows 上 Python 做剪贴板"的可行性佐证，但不宜依赖。

> **结论**：🟡 仅参考可行性，代码不搬。

#### ⑤ CopyQ（C++）— 功能蓝本 + 架构参考

- **语言**：C++ / Qt | **许可**：GPL-3.0 | 12.1k star，持续维护。

**可复用性评估**：
- **不可直接复用**（C++ + GPL-3.0 双重阻碍）。
- **极高参考价值**：① 其文档（README / docs）是一份完整的"剪贴板管理器需求规格书"；② 命令/脚本系统、标签页、忽略规则等功能设计值得借鉴；③ 它同样基于 Qt，类/信号体系与 PySide6 相通，`qxt` 子库中的全局热键实现可读源码理解原理。

> **结论**：🟡 功能与架构双参考（读文档 + 读源码学思路）。

#### ⑥ Ditto（C++）— Windows 最佳实现参考

- **语言**：C++ / Win32 | **许可**：GPL-3.0 | 7k star。

**可复用性评估**：不可直接复用（C++ + GPL-3.0）。但其三件事值得我们重点研究：① **SQLite 存储历史**的设计；② **"粘贴回上一窗口"**的实现（设置剪贴板 + 向前台窗口发送 Ctrl+V）；③ **忽略规则**（避免记录密码等）。

> **结论**：🟡 读源码学 Windows 端最佳实践。

#### ⑦ 1Clipboard（Electron）— 不可复用

- **语言**：Electron/Angular | **许可**：无（license: null）| 停更。

**可复用性评估**：🔴 无许可证 + 技术栈不符 + 停更，完全不可复用。唯一价值是反面教材。

#### ⑧ Linux 方案（cliphist / nwg-clipman / Klipper 等）— 思路参考

- `nwg-clipman`（Python + GTK3，MIT）：给 cliphist 做 GUI，活跃。
- `clips`（Python + GTK，GPL-3.0）：多格式剪贴板管理器。

**可复用性评估**：平台不符（GTK/Linux），不可直接复用；但 **cliphist 的"存储与选择界面分离"** 和 `nwg-clipman` 的简洁 UI 思路可借鉴。

## 六、复用性结论

**一句话总结：市场上没有"可直接拿来用"的 Python + PySide6 + Windows 现成剪贴板管理器，但有 1 个同栈开源项目（jietuba）提供高质量的架构与代码参考，若干老牌项目提供功能与实现思路。**

| 复用层级 | 来源 | 具体怎么用 |
|---|---|---|
| **架构蓝本** | jietuba 的 `main/clipboard/` 模块 | 照它的 controllers/core/services/ui 分层来组织我们的代码；核心模型（ClipboardItem/Group）可直接借鉴设计 |
| **代码复用（MIT）** | jietuba 的 Qt 剪贴板逻辑 | 监听（`QClipboard.dataChanged`）、去重、历史管理可参考/改写自其代码，注明出处 |
| **功能规格** | CopyQ 文档、Ditto、ClipboardFusion | 从成熟产品收敛出我们的功能清单（历史/搜索/固定/分组/忽略/粘贴回上一窗口） |
| **Windows 实现细节** | Ditto（SQLite/粘贴回上一窗口）、CopyQ qxt（全局热键）、jietuba（快捷键/平台工具） | 读源码理解原理后在 PySide6 里用 `ctypes`/`pywin32`/`QHotkey` 实现 |
| **扩展机制** | infinitecopy 的 pre/post 插件钩子 | 设计我们的"剪贴板动作"扩展点 |

## 七、对我们开发的启发：关键技术要点

基于调研，构建 PasteBoard 时应该重点考虑以下技术选型（具体实现留待后续设计阶段）：

| 技术点 | 推荐方案 | 说明 |
|---|---|---|
| **剪贴板监听** | `QApplication.clipboard().dataChanged` 信号 | Qt 在 Windows 上封装了 `WM_CLIPBOARDUPDATE`（`AddClipboardFormatListener`），事件驱动、省电可靠；备选方案是定时轮询（简单但不优雅） |
| **历史存储** | SQLite（Python 标准库 `sqlite3`） | Ditto 验证过的方案：容量大、查询快、单文件、无额外依赖 |
| **图片存储** | SQLite BLOB 或磁盘文件 + 缩略图 | 历史图片转存 PNG/缩略图，避免占用内存（Qt `QPixmap` 大图很吃内存） |
| **全局热键** | `QHotkey`（PySide6 生态）或 `RegisterHotKey`（ctypes） | 用于"唤出主窗口""快速粘贴第 N 条" |
| **系统托盘** | `QSystemTrayIcon` | 常驻后台、开机自启（注册表 Run 项） |
| **一键粘贴** | 设置剪贴板 + `SendInput` 模拟 `Ctrl+V` 到前台窗口 | Ditto/CopyQ 标准做法：先记住"激活我们的窗口之前"的前台窗口，粘贴时把焦点还给它 |
| **去重** | 内容哈希（文本/图片指纹） | 连续复制相同内容只保留一条，并顶到最前 |
| **忽略规则** | 程序名黑名单（如密码管理器）、输入框类型（密码框） | 避免把敏感内容写进历史 |
| **打包** | PyInstaller（--onefile / --noconsole） | 用户已有 PyInstaller 经验；参考 jietuba 用 PyInstaller 单文件 42MB 的实践 |
| **扩展点** | "剪贴板动作"钩子（pre/post） | 借鉴 infinitecopy，为将来的格式转换/自动处理预留接口 |

**建议的首版功能范围（MVP）**：后台监听 + 历史（文本/图片）+ 搜索 + 固定 + 系统托盘 + 全局热键唤出 + 一键粘贴回上一窗口 + 去重。**云同步、加密、局域网共享、脚本系统暂缓**（符合 YAGNI，也符合"本地优先"的定位）。

## 九、附录：剪贴板管理核心概念速览

| 概念 | 说明 |
|---|---|
| CF_UNICODETEXT / HTML / BITMAP | Windows 剪贴板的标准格式：文本、富文本、位图。管理器按需优先保存哪些格式 |
| WM_CLIPBOARDUPDATE / AddClipboardFormatListener | Windows 官方"剪贴板内容变化"通知机制（事件驱动监听的底层原理） |
| 剪贴板链（Viewer Chain） | 老式监听方式（SetClipboardViewer），现代应用多用 Format Listener 替代 |
| 粘贴回上一窗口 | 管理器"借用"剪贴板后，把焦点还给用户之前所在的窗口，再模拟 Ctrl+V |
| 去重/忽略 | 连续相同内容合并；对密码框、指定程序不记录 |
| QClipboard / QMimeData | Qt 对系统剪贴板的封装：`text()`、`html()`、`imageData()`、`dataChanged` 信号 |
